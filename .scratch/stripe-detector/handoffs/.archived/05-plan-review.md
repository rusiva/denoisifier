- [x] B4 — settled by plan 2.3 lines 'Candidates are built without reference to the threshold' and step 7 (score = highest peak over qualifying groups; regions = qualifying groups with peak > threshold), plus the threshold-sweep verdict test. See B7 for one hole left in step 9.
  Original: B4 break: "`striped == bool(regions)` by construction" (2.3 step 6) does not hold as written, for two reasons. (i) The score test runs on unsplit `{ratio > t}` components, but steps 1-3 split a core by Period **before** the size test. A component that passes unsplit can split into two cores that each fail, so `score > T` while `regions == ()`. (ii) Bisection assumes "some component passes at level t" is monotone in t. It is not: as t drops, components merge and the merged component's median bank Period can jump (a P5 core merging with a P16 neighbour), which raises its size requirement. So the bisection can land below the true maximum, or on either side of T, unlike the direct test at T. → plan change: use one component test for both, with the same split, the same size rule and the same Period, in score and regions. Compute the score by an exact descending sweep (union-find max-tree, testing each component at each merge) rather than bisection. Or define regions T-free: candidates from a fixed seed level or regional maxima, grown and size-tested once, `score` = max peak ratio over the passing candidates, and regions = the candidates with peak > T. Then the invariant holds exactly, and the test in `test_verdict_is_striped_exactly_when_a_region_is_reported` stays a check, not a hope.

- [ ] B7 break (new, from the fold): plan 2.3 step 9 drops 'a group whose labelled area becomes empty' after overlap resolution, and resolves overlaps only among **reported** groups (those with peak > threshold). Both steps depend on the threshold, which 2.3 promises nothing does. Case 1: with two reported groups, the one with the lower depth on the overlap can be emptied and dropped. If its peak was the score, `score > threshold` still holds while that region is gone, and at a threshold between the two peaks the score's group would be the only one reported and so not emptied. Case 2: at a lower threshold an extra group enters the overlap resolution and changes the earlier groups' `labels`, `bbox` and `area_px`, so 'regions at a lower t include those at a higher t' only holds for Period/Angle/depth. → plan change: resolve overlaps and drop empty groups among **all qualifying groups** (T-free), **before** the score. Score = highest peak over the surviving qualifying groups; then filter by threshold. State in the verdict test that bbox/area are also threshold-invariant.
